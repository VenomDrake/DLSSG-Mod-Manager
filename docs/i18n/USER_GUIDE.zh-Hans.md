<a id="start"></a>
## 1. 快速开始：第一次测试

在应用中打开**使用教程**，选择**开始引导教程**即可跟随八个实用步骤。你可以搜索主题、点击设置旁的 **?**，或在该控件获得焦点时按 **F1**。**在管理器中显示**会打开并突出显示对应控件，不会应用任何更改。

1. 关闭游戏。选择一款**离线单人游戏**。
2. 打开管理器，等待所选技术的安装包检查结束。
3. 选择技术，再从 Steam 列表选择游戏，或选择游戏文件夹/EXE，等待分析完成。
4. 阅读 **2 · 查看结果**，到**诊断**中查看完整列表。解决所有**已阻止**项目，并在继续前阅读警告。
5. 在**模组设置**中保留首次测试的默认值：**SM86：DLSS、2×**；**ANR：Auto、2×**；**OptiScaler：自动超分辨率，帧生成输入和输出都关闭**。
6. 返回**游戏管理**，点击**安装模组**。核对确认窗口中的目标位置和设置，再确认并等待完成。
7. 启动游戏，按[对应技术的游戏内步骤](#in-game)操作。短时间游玩，观察运动画面、HUD 和操作响应。
8. 在**诊断**中读取日志。使用 OptiScaler 时，还要在游戏内按 **Insert** 查看实际启用的输出。仅仅加载 DLL 并不能证明帧生成成功。

首次测试正常后，每次只改**一个设置**。先关闭游戏，在管理器中应用修改，再重启游戏进行对比。

<a id="safety"></a>
## 2. 修改游戏前必读

**这些模组只应用于离线单人游戏。修改游戏文件可能触发反作弊或导致封禁。** 管理器不提供反作弊绕过，也不能防止封禁。选择离线模式并不保证游戏没有反作弊；发现反作弊时，管理器仍会阻止安装。

管理器检查文件和必要条件。**“已检测到所需条件”不等于保证游戏兼容、运行稳定或 FPS 提高。** 请另外备份重要存档。管理器的备份覆盖它修改的游戏文件，并不是全部存档或整个游戏。

不要手动叠加加载器，不要用来历不明的 DLL 覆盖游戏文件，也不要只为让检查通过而删除冲突文件。先弄清已有模组的情况。原始项目的二进制文件以数据形式从原始仓库下载；管理器不会运行其安装脚本。

<a id="install"></a>
## 3. 下载并打开管理器

请使用[管理器的官方发布页](https://github.com/VenomDrake/DLSSG-Mod-Manager/releases/latest)。

| 下载类型 | 使用方法 |
|---|---|
| **便携版 ZIP** | 将**整个 ZIP** 解压到可写入的文件夹，然后打开 `DLSSGModManager.exe`。不要直接在 ZIP 内运行。许可证和说明文件应与程序保存在一起。 |
| **Windows 安装程序 (.msi)** | 关闭管理器后运行 MSI。它为当前 Windows 用户安装程序并创建快捷方式。 |

发布的安装包已包含管理器所需的 .NET 运行时。你不需要另外安装 Python、CUDA Toolkit 或解压程序。所选技术仍可能需要显卡驱动、Visual C++ 或 Vulkan 组件，这些会单独检查。

管理器和 MSI 未签名。只使用你确实想下载的项目发布文件，不要全局关闭 Windows 安全防护。首次启动需要联网获取技术安装包。之后可能可以离线使用已验证的缓存包，但**有离线缓存不代表已经确认它是最新版本**。

<a id="choose-provider"></a>
## 4. 应该选择哪种技术？

在**超分辨率和帧生成**中选择。本教程也把一项技术称为一个**提供程序**。

| 选项 | 用途和首次测试要求 |
|---|---|
| **DLSSG for SM86 · NVIDIA / XeSS** | 管理器为 NVIDIA **RTX 20/30** 提供的已审核方案，需要 **R580 或更新驱动**、已配置的硬件加速 GPU 计划（HAGS），以及游戏内受支持的原生 DLSS Frame Generation 运行库。游戏使用 DirectX 12。先用 DLSS 和 2×。 |
| **Apex Neural Rendering · 测试版** | 另一种 FG 提供程序，本管理器支持声明范围内的 **GTX 16 / RTX 20–50** 和 **Radeon RX 5000/6000/7000/9000**。游戏须通过 DX12/Vulkan 提供原生 x64 DLSS Frame Generation，还需 Visual C++ x64 和 Vulkan 加载器。GTX 10/Pascal、Intel Arc 不在本管理器的 ANR 支持范围内。先用 Auto 和 2×。ANR 本身仍是测试版。 |
| **OptiScaler · 超分辨率 / 帧生成** | 替换兼容游戏的 DLSS/FSR/XeSS 时域超分辨率，也可管理支持的 FG 路径。**只使用超分辨率时，不要求游戏有原生 DLSS Frame Generation**。NVIDIA、AMD、Intel 都可作为候选，但每种输出另有条件。先用自动超分辨率，并将 FG **输入/输出都关闭**。 |

HAGS 和 NVIDIA R580 **不是自动套用于 ANR 或 OptiScaler 的统一要求**。OptiScaler 的原生 **DLSS 输出**仍需要 NVIDIA RTX 和游戏的 DLSS 运行库。OptiScaler 并不能让所有后端在所有显卡上工作。

管理器 0.5.2 已审核的安装方案为 **SM86 0.4.1/0.4.2**、**ANR FG-V.B15/B17**、**OptiScaler 0.9.5**。上游新包的要求尚未审核时，即使下载完成也可能不能安装。

管理器会记住所选提供程序，**不会根据显卡自动选择最佳方案**。看到显卡检查失败时，请先确认是否选了适合的技术。

<a id="first-install"></a>
## 6. 安装、修改设置或切换技术

1. 等待安装包下载和验证结束，选择正确的渲染 EXE。
2. 阅读摘要和全部检查。关闭游戏及残留的游戏进程。
3. 使用首次测试默认值，或设置你想使用的选项。某个设置引入额外要求时，检查结果可能变化。
4. 点击底部操作按钮，核对确认窗口中的技术、渲染文件夹、版本和设置。
5. 确认后，管理器准备已验证文件、创建备份、停用旧加载器、修改数据，最后激活新加载器。等待完成。
6. 重新启动游戏。已经打开的游戏不能可靠地使用刚写入的设置。

**“您已拥有最新版本”指的是已安装包的身份信息。** 它不表示刚修改的设置已经应用。请关闭游戏，再点击**应用设置**来保存这些更改。

对于管理器管理的安装，切换提供程序也使用相同的备份和历史机制。独立 OptiScaler 0.9.5 与 ANR 自带的定制 OptiScaler 加载器不同，管理器不会把它们混在一起。从外部 ANR Addon 切换时，可能需要先还原外部安装。未知的手动安装会受到保护，不会被悄悄覆盖。

<a id="checks"></a>
## 7. 正确理解检查结果

| 状态 | 含义和处理方式 |
|---|---|
| **已通过** | 当前这一项检查成功，不代表其他条件或实际游戏也已经验证。 |
| **信息** | 提供背景信息，例如某项设置或可选组件；按需要阅读。 |
| **警告 / 待验证** | 需要留意或在游戏中确认。不会自动阻止安装，但也不保证继续就安全或兼容。 |
| **未知** | 管理器无法确认某个事实。阅读详情，不要当成已经通过。 |
| **已阻止** | 原因解决前不能继续安装。 |

常见检查包括：Windows/x64、显卡和驱动、适用时的 HAGS、Visual C++/Vulkan、安装包身份与受支持结构、扫描完整性和权限、正确 EXE、原生输入/运行库、图形 API 证据、反作弊迹象、已有或被修改的加载器、游戏进程、只读目标、可用空间。备份和文件准备需要的空间比最终模组大小更多。

**不受支持**表示发现了技术条件不符。**需要检查**表示证据不完整、EXE 不明确，或者输入可能内置在游戏中。**安装已阻止**也可能是文件冲突或安装包问题，并不一定表示游戏不兼容。静态扫描不能证明没有反作弊，也不能保证游戏正常工作。

<a id="sm86"></a>
## 8. SM86：管理器中的每一项设置

![SM86 设置](../settings-sm86.png)

**首次测试建议：** DLSS、2×、内核优化 1、预设 A、SR 覆盖关闭、日志 2、帧耗时记录关闭、`version.dll`。

| 设置 | 简单说明和可选值 |
|---|---|
| **生成引擎** | **NVIDIA DLSS-G** 或 **Intel XeSS-FG** 选择模组的帧生成实现。这里的 XeSS 是 SM86 模组自己的实现，不表示普遍支持 Intel 显卡。先选择 DLSS。 |
| **帧数倍率** | DLSS 提供 **2×–6×**，XeSS 提供 **2×–4×**。这是请求的倍率：2× 表示每个真实帧增加一帧，3× 增加两帧，以此类推。游戏可能限制倍率；不受支持的请求可能使 FG 无法启用。更多生成帧不等于延迟按比例降低，也不保证更流畅。先用 2×。 |
| **内核优化** | **0：**原始内核，可作比较。**1：**保持精确输出的加速，推荐。**2：**更快的近似处理。**3：**最大程度的近似。较高档可能改变结果；请比较运动边缘和 UI，不要直接认定数字越大越好。仅对 DLSS-G 生效。 |
| **DLSS-G 预设** | **A：**正常的首次测试选择。**B：**游戏提供合适的无 HUD 图像和 UI 缓冲区时进行界面重组，不能凭空生成这些缓冲区。**C：**较轻的 FG，可能牺牲画质，尤其是 HUD 和遮挡边缘。仅对 DLSS-G 生效。 |
| **超级分辨率覆盖** | **Off** 保留游戏自身的超分辨率。**M-INT8 / L-INT8** 选择本项目的 M/L INT8 内核，**M-FP16 / L-FP16** 使用相应的 FP16 处理。M/L 是模型选择，不是统一速度排名。在质量、平衡、DLAA 模式可能降低性能，首次测试保持 Off。 |
| **XeSS 光流** | **Coarse、Middle、Fine** 改变光流处理分辨率，越精细可能越耗 GPU 时间。**CoarseAt4K** 在输出像素总数至少为 3840×2160 时使用 Coarse，否则使用 Middle。首次用 Middle。仅对 XeSS-FG 生效。 |
| **XeSS 界面处理** | **Auto**、**要求无 HUD 图像 (1)**、**不使用无 HUD 图像 (0)**。已审核的 SM86 **0.4.2 中 Auto 与 0 相同**：整个图像连同 UI 一起插帧。模式 1 需要游戏提供匹配的无 HUD 图像，否则可能失败。 |
| **日志详细程度** | **0 关闭**、**1 错误**、**2 诊断（推荐）**、**3 详细跟踪**。更详细有助排查，但会增加记录量。 |
| **记录帧耗时** | 写入用于排查的额外计时数据，不是 FPS 上限，也不会启用 FG。首次保持关闭。 |
| **加载器 DLL** | `version.dll`（推荐）、`winmm.dll`、`dbghelp.dll`、`dinput8.dll`、`dxgi.dll`、`d3d12.dll`。文件名决定游戏如何加载模组。保持一个活动加载器；模组不加载时通过管理器尝试其他选项，不要手动堆放副本。 |

DLSS-G 和 XeSS-FG 使用不同参数。界面中能看到某个引擎专用选项，不代表选择另一个引擎时它也会生效。

**SM86 的 HAGS：**从诊断打开 Windows 图形设置，如果 Windows 提供硬件加速 GPU 计划，就启用并重启 Windows。已配置与实际生效是不同检查；运行时状态由游戏日志确认。管理器不会自动修改驱动或 HAGS。

<a id="anr"></a>
## 9. ANR：管理器中的每一项设置

![ANR 设置](../settings-anr.png)

**首次测试建议：** Auto 计算路径、2×、每单位 80 尼特、场景切换处理开启、`dxgi.dll`。引擎是 ANR；SM86 的内核优化、预设和 SR 覆盖不适用。

| 设置或模式 | 含义 |
|---|---|
| **Full / Addon** | 自动选择。**Full** 包含审核过的加载器和提供程序配置。**Addon** 将 ANR 添加到兼容的外部 OptiScaler 安装中，保留其加载器。管理器管理的独立 OptiScaler 切换为 ANR 时使用 Full。不要手动选择或复制任意 addon。 |
| **帧数倍率** | 请求 **2×–6×**，仍受游戏集成限制。先用 2×。管理器写入对应的额外帧数；选择 6× 不表示额外增加六帧。 |
| **计算路径** | **auto、coopmat、packed、dp4a、portable、portable-linalg、portable-xmx** 是 ANR 的不同计算实现，不是画质档位。Auto 使用提供程序的选择逻辑；指定路径需要对应 GPU 能力，不保证每种都能工作或更快。不是排查特定问题时，请保留 Auto。 |
| **HDR 亮度** | 范围 **40–1000**，默认 **80**，表示提供程序 HDR/PQ 处理中线性值 1.0 对应的亮度，不是显示器亮度滑块。除非正在排查 HDR 问题，否则保留 80。 |
| **场景切换处理** | 默认开启，避免在突然切换的画面间插帧。正常测试保持开启。 |
| **加载器 DLL** | `dxgi.dll`、`winmm.dll`、`version.dll`；先用 `dxgi.dll`。Addon 模式保留外部加载器，选择器锁定。 |

即使管理器是稳定版，ANR 的 **Beta** 标签仍描述上游提供程序。ANR 需要已审核的 Visual C++ x64 组件及 Vulkan 加载器，即使游戏使用 DX12。这里不套用 SM86 的 HAGS 要求。

<a id="optiscaler"></a>
## 10. OptiScaler：管理器中的每一项设置

![OptiScaler 设置](../settings-optiscaler.png)

**首次测试建议：**所有超分辨率设为 **Auto**、FG 输入**关闭**、FG 输出**关闭**、DXGI GPU 身份模拟 **Auto**、日志 **2 · 信息**、加载器 `dxgi.dll`。

### 超分辨率选择

**输入**指游戏菜单中选择的技术，**输出**指 OptiScaler 实际运行的技术。例如，游戏提供 DLSS 输入，但 OptiScaler 实际输出 XeSS。因此，游戏里选择 DLSS 本身不能证明实际输出也是 DLSS。

| 管理器字段 | 可选值 |
|---|---|
| **DirectX 11 超分辨率** | Auto；FSR 2.2 (`fsr22`)；FSR 3.1 (`fsr31`)；原生 XeSS (`xess`)；经 D3D11on12 的 XeSS (`xess_12`)；经 DX12 互操作的 FSR 2.1/2.2/3.1 (`fsr21_12`、`fsr22_12`、`fsr31_12`)；DLSS。 |
| **DirectX 12 超分辨率** | Auto；XeSS；FSR 2.1；FSR 2.2；FSR 3.1/4；DLSS。 |
| **Vulkan 超分辨率** | Auto；后端支持范围内的原生 FSR 2.1/2.2/3.1/4；原生 XeSS；经 DX12 互操作的 FSR 2.1 或 FSR 3.1/4 (`fsr21_12`、`fsr31_12`)；DLSS。 |

游戏当前使用哪个 API，就采用对应字段。**Auto** 遵循 OptiScaler 默认值，是最稳妥的起点，不保证输出最快。`_12` 表示经 DX12 互操作路径，可能有额外开销。

原生 **DX11 XeSS** 需要 Intel Arc；`xess_12` 是不同的互操作选项。**DLSS 输出**需要 NVIDIA RTX 和游戏的 x64 DLSS 运行库。**FSR 3.1/4** 不保证所有显卡都运行 FSR 4，实际模型或回退取决于后端和硬件。请在覆盖界面中确认实际输出；管理器不会强制启用不受支持的 FSR 4。

在 DX11 下，原生 `fsr31` 路径是 FSR 3.1；FSR 4 路径使用 DX12 互操作。“3.1 / 4”这样的通用标签不代表原生 DX11 FSR 4 保证可用。

### 帧生成输入与输出

首次只测试超分辨率时，将**两个字段都关闭**。以后启用 FG 时，必须选择兼容的输入**和**输出。只开启一个字段会被阻止。

| FG 输入 | 游戏必须提供的条件 |
|---|---|
| **关闭** (`nofg`) | 不请求 OptiScaler FG，同时将输出关闭。 |
| **DLSS Frame Generation** (`dlssg`) | 合适的 Streamline 2 集成和原生 DLSS FG。管理器检查可获取的证据，不能确认时会警告。 |
| **DLSS-G · Nukem** (`nukems`) | 原生 DLSS-G 运行库。此输入必须配 **Nukem · FSR 3** 输出。 |
| **FSR Frame Generation** (`fsrfg`) | 游戏中兼容的原生 FSR FG 来源。仅有 DLL 文件名不足以确认集成。 |
| **超分辨率输入 / OptiFG** (`upscaler`) | 已正常工作的时域超分辨率输入，使用已审核的 DX12 OptiFG 路径。可能要在上游覆盖界面中校正 HUD。 |
| **FSR 3.0 Frame Generation** (`fsrfg30`) | 兼容的原生 FSR 3.0 FG 来源。 |

| FG 输出 | 含义 |
|---|---|
| **关闭** | 不输出 FG，同时将输入关闭。 |
| **AMD FSR Frame Generation** (`fsrfg`) | 使用兼容的 FidelityFX FG 后端，不保证每块显卡上的 FSR 版本和功能相同。 |
| **Intel XeSS Frame Generation** (`xefg`) | 需要后端要求的 GPU 能力，包括适合的 DP4a 支持，以及对应的游戏/显示条件。仅识别为 Intel、AMD 或 NVIDIA 并不代表能够启用。多帧生成还有上游限制。 |
| **Nukem · FSR 3** (`nukems`) | 使用已审核并随包提供的 DLSSG-to-FSR3 路径；选择 Nukem 输入时必须用这个输出。 |

管理器 0.5.2 会在检测到 **DX11** 路径时阻止所选 FG。检测到 **Vulkan** 时，已审核允许的 FG 配对是 **Nukem → Nukem**。其他列出的 FG 路径需要 DX12；API 不明确时仍须在游戏内确认。这些控件不能让本来不支持的游戏集成变得兼容。

### 其他控件与高级设置

| 设置 | 含义 |
|---|---|
| **DXGI GPU 身份模拟：Auto / 开启 / 关闭** | 为兼容性而改变通过 DXGI 报告的 GPU 身份，不会升级真实显卡，也不保证性能提高。先用 Auto。这不是反作弊保护，只能在离线游戏中使用模组。 |
| **日志详细程度** | **0 跟踪**、**1 调试**、**2 信息（推荐）**、**3 警告**、**4 错误**。与 SM86 不同，**0 不表示关闭日志**。管理器会启用文件日志用于诊断。 |
| **加载器 DLL** | `dxgi.dll`、`winmm.dll`、`version.dll`、`d3d12.dll`、`dbghelp.dll`、`wininet.dll`、`winhttp.dll`。先用 `dxgi.dll`；需要修改时关闭游戏，通过管理器更换。 |

在游戏内按 **Insert**，打开完整的 OptiScaler 覆盖界面，查看高级设置和实际后端信息。大量高级控件属于 OptiScaler；管理器提供的是上面已审核的常用选项。保留能工作的初始方案，每次只改一个参数；管理器以外的功能请参阅[官方说明](https://github.com/optiscaler/OptiScaler/wiki)。稳定版 0.9.5 与 v10 nightly 的说明不能混用。

从管理器应用设置时，它会再次写入所选值。如果你在覆盖界面改过相同选项，应用前先让管理器的选择保持一致。在支持的情况下，无关 INI 设置会保留。

<a id="in-game"></a>
## 11. 在游戏里应该怎么设置

**SM86 或 ANR：**安装后启用游戏的 **NVIDIA DLSS Frame Generation**。游戏提供时先选 2×；菜单要求重启就重启游戏。Quality、Balanced 等超分辨率质量选项与 FG 是不同设置。

**OptiScaler 首次测试：**在游戏中开启兼容的时域超分辨率，管理器的 FG 输入/输出保持关闭，按 Insert 查看实际输出。只测试超分辨率不必开启 DLSS FG。以后选择某种原生 FG 输入时，再启用对应的游戏功能。使用 Upscaler/OptiFG 输入时，采用已审核的 DX12 路径并遵循上游覆盖界面的说明。

灰色的 **2×** 选项可能只是表示只能使用这个倍率，**不能证明 FG 已在运行**。管理器不能解锁每款游戏菜单里的所有倍率。同样，游戏菜单上的名称可能描述输入，而 OptiScaler 实际使用另一种输出。

对比时使用相同场景、分辨率和设置。除了 FPS 和操作响应，也要看运动文字、栅栏、人物边缘和 HUD。生成/显示 FPS 与真实渲染 FPS 不同，显示更多帧不等于操作响应翻倍。

<a id="verify"></a>
## 12. 诊断：如何确认发生了什么

短时间测试后，在**诊断**中点击**读取游戏日志**。通过管理器启动游戏，以及读取日志，都会在管理器打开期间启动定期读取。如果结果仍在等待，关闭游戏，再读取写完的日志。

| 提供程序 | 管理器可以确认的内容 |
|---|---|
| **SM86** | 查找匹配的记录会话中是否成功创建 FG 功能并首次执行。仅加载模组或发现 SR 功能不足以确认。还要阅读错误及运行时 HAGS/GPU 信息。 |
| **ANR** | 区分加载、初始化和真正生成帧的执行。FG 确认需要完整会话、正数的生成执行计数和零生成错误。计数及记录倍率有助排查。 |
| **OptiScaler** | 报告加载和当前会话中的日志错误。DLL 加载或交换链创建**不能证明 SR、FG 成功或性能提高**。请在游戏覆盖界面中查看实际后端、帧统计和视觉结果。 |

不完整、尚未写完或过大的日志不能确认整个会话完全成功。**没有错误**只表示读取器理解的那部分没有发现错误，不代表性能或 FG 已获验证。核对会话时间，避免把旧测试当作当前结果。多显卡电脑还要确认游戏实际使用哪块显卡。

<a id="updates"></a>
## 13. 三种不同的更新

| 更新对象 | 工作方式 |
|---|---|
| **管理器程序** | 启动时检查 GitHub 稳定版，保持打开时也定期检查，约每六小时一次。只有新稳定版才显示小提示。选择**更新并重启**后，程序经你同意下载并验证相应 ZIP/MSI，然后更新和重启。重新打开管理器可立即检查。正常稳定版检查会忽略预发布版。 |
| **已下载的提供程序安装包** | 启动或选择技术时检查相应包；包旁的 ↻ 可以重新检查。新验证的下载会更新缓存，但**不会自行应用到游戏**。 |
| **某款游戏中的模组** | 选择并分析该游戏，通过检查和确认后点**更新模组**。其他游戏仍保留原安装，直到分别更新。 |

管理器比较发布 ID、资源 ID 和 SHA-256，所以相同可见版本下替换过的文件也能被发现。**已下载**、**最新版本**、**离线缓存**、**本管理器尚不支持**是不同结果。文件完整性可以通过，但安装方案仍可能未知。请等待明确支持它的管理器版本，不要手动复制 DLL 强行绕过。

管理器 **0.4.3 及以后**使用新仓库名称。**0.4.2 或更早**可能需要手动安装一次最新完整 MSI/便携包。0.2.0/0.2.1 MSI 更新器弹出帮助窗口或错误 1639 的问题，也需要手动安装一次已修复的新 MSI。保持原安装类型并先关闭管理器。保留游戏和备份文件夹。

<a id="backup"></a>
## 14. 禁用、重新启用、还原和切换提供程序

**禁用模组**暂时阻止管理器所管理的模组激活，不是完全卸载。通常只停用加载器，保留运行库和备份。对于外部 ANR Addon，会还原外部 OptiScaler 的选择，同时保留其加载器。

要**重新启用**，关闭游戏，再对所选的受管理提供程序使用主要安装/更新操作。

**还原先前状态**使用与当前受管理安装、更新或提供程序切换关联的备份。它不是“撤销上一次按钮”的通用功能，也不专门用于撤销禁用。根据历史状态，它可能还原旧模组版本、其他提供程序、已禁用的安装，或没有模组的原始状态。还原首次安装前的备份可能移除活动模组。请阅读确认窗口。

旧安装记录可以指向更早的备份，因此记录还存在时，继续还原可能进一步回到以前的安装状态。没有通用的历史重做浏览器。备份会保留；遇到已修改或未知文件时，管理器可能阻止还原，而不是覆盖它们。

**不要为消除错误而手动删除** `.dlssg-manager.json`、`.dlssg-manager.transaction.json` 或 `.dlssg-manager-backups`。它们保存文件归属和恢复信息。操作中断后，关闭游戏，保留这些文件并重新打开管理器。恢复会在文件操作中使用事务日志。如果仍然阻止，导出报告求助，不要手动重新激活或删除加载器。

<a id="troubleshooting"></a>
## 15. 常见问题及下一步

| 现象 | 应对方法 |
|---|---|
| **安装按钮不可用** | 等待当前操作结束，选择真正 EXE，到诊断查看已阻止项目。只读/UI 预览版不能安装。请解决原因，不要手动复制文件。 |
| **显卡不受支持** | 先看所选提供程序。管理器会记住或使用默认选项，不自动为显卡挑选最佳方案。ANR、OptiScaler 与 SM86 要求不同。 |
| **游戏不受支持 / 需要检查** | 读具体原因。缺少原生 FG 会影响 SM86/ANR；OptiScaler 则可能需要时域 SR 输入证据。内置 FSR 输入不一定能判断。检查游戏 API 和 EXE。 |
| **包已最新但仍阻止安装** | 完整性/最新状态与已审核的安装方案、硬件条件、游戏兼容性是分开的。未知新方案需要管理器更新和审核。 |
| **Steam 列表空或缺少游戏** | 刷新 Steam 库，否则手动选择游戏文件夹或实际渲染 EXE。 |
| **多个 EXE** | 优先选择真正渲染器。Unreal 游戏查看 `Binaries\Win64` 及 `Shipping.exe` 候选。不要为了绕过不确定性而选启动器或崩溃报告程序。 |
| **游戏仍在运行** | 完全退出并等待进程结束，再安装、改设置、切换或还原。 |
| **已配置 HAGS，运行时仍未确认** | 对 SM86，启用后重启 Windows，测试游戏并读取最新日志。注册表设置本身不能证明该会话中 HAGS 已生效。 |
| **缺少 Visual C++ / Vulkan** | 使用 Microsoft 或显卡厂商的官方安装程序，不要去下载单个 DLL 的网站。ANR 需要已审核的 Visual C++ x64 组件和 Vulkan 加载器，安装后重新检查硬件。 |
| **未知加载器、手动模组或已修改文件** | 先保留。识别原模组，并按它支持的方法还原/移除，或附报告求助。管理器故意保护外部文件，不会悄悄接管手动 OptiScaler。 |
| **日志缺失 / 仅已加载 / 2× 灰色** | 按对应技术完成游戏内步骤，短时间游玩，再读完整日志。完全没加载时可能需要换加载器。灰色 2× 或只加载不证明 FG。 |
| **拖影、闪烁、卡顿或 FPS 更低** | 返回推荐默认值。一次只改一个选项，适当降低 FG 请求并看错误。可用管理器禁用/还原。不是倍率最高、光流最细、近似档最高就一定最好。 |
| **修改设置没有效果** | 关闭游戏，应用设置，再重启。确认所选引擎和实际 API；其他引擎/API 的参数可能无关。 |
| **操作中断或无法还原** | 游戏保持关闭，保留记录和备份。读错误、导出报告并求助。不要删除恢复事务日志，也不要用未知文件覆盖备份。 |
| **看不到管理器更新** | 重新打开管理器，检查网络和已装版本。正常检查忽略预发布。非常旧的版本可能需要上面的一次手动更新。 |

<a id="files"></a>
## 16. 文件、隐私和求助

程序设置、缓存和 `application.log` 通常位于 `%LOCALAPPDATA%\DLSSGModManager`。自定义数据目录或专用 UI 预览启动可能使用其他位置。游戏的归属记录、事务日志和备份在**渲染 EXE**旁，不一定在启动器旁。

| 提供程序 | 相对于渲染文件夹的正常游戏日志位置 |
|---|---|
| SM86 | `dlssg_sm86\logs\dlssg_sm86.log` |
| ANR | `OptiScaler\custom\Apex Neural Rendering FG\dlssg\nr_fg-*.log` |
| OptiScaler | `OptiScaler.log` |

在诊断中使用**导出诊断报告**，选择 `DLSSG-diagnostic-report.json` 保存位置。报告包括管理器/提供程序/包版本、包哈希与更新状态、显卡/驱动、检查和可用日志证据。所选游戏根路径和用户资料路径前缀会替换成 `<GAME>`、`<USER>` 等占位符。分享前仍须检查，因为这不保证去掉所有可能识别身份的字符串。

报告只保存在本地，不会自动发送。程序不需要账号，也没有遥测。求助时请提供技术、游戏、管理器版本、准确阻止消息以及改过什么。结果截图和导出报告比“不能用”更有帮助。不要分享令牌、密码或无关私人文件。

<a id="glossary"></a>
## 17. 简单术语表

| 词语 | 通俗含义 |
|---|---|
| **渲染/基础 FPS** | 游戏实际计算出来的真实帧。 |
| **帧生成 / FG** | 在真实帧之间加入估算的额外帧。 |
| **超分辨率 / SR** | 从较低分辨率渲染重建高分辨率图像，与 FG 是不同功能。 |
| **输入 / 输出** | OptiScaler 拦截的游戏功能 / OptiScaler 替代运行的后端。 |
| **API：DX11、DX12、Vulkan** | 游戏使用的图形接口；不同 API 有不同支持路径。 |
| **HUD / 无 HUD** | 屏幕上的游戏界面 / 不包含该界面的游戏图像。 |
| **DLL / 加载器 / 代理** | 代码库和让游戏载入模组的特定文件；文件名有实际作用。 |
| **HAGS** | Windows 硬件加速 GPU 计划。 |
| **运行时/运行库** | 某功能需要的软件组件，例如游戏 DLSS DLL 或 Visual C++。 |
| **缓存 / SHA-256** | 保存的下载包 / 用来检验完整性的指纹。匹配指纹不证明游戏兼容，也不会让未知方案变成受支持。 |
| **备份 / 事务日志** | 先前文件状态 / 用于恢复中断修改的信息。 |
